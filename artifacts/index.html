What we are building

An Arch-based system.
Keyboard first. Agent ready.

rukiOS is a terminal and TUI driven Linux distribution. People and integrated AI agents use the same clear commands, system tools, and inspectable filesystem interfaces to understand and manage the machine.

Required in the product

What the requirements call for

OSDistribution foundation

  • Arch Linux base, Linux kernel, and Arch package ecosystem.Reuse pacman, systemd, NetworkManager, and established Linux tools.
  • Rust-based ruki CLI and TUI as the system's user-facing control layer.
  • Deliver core system settings and workflows in terminal interfaces, not GUI control panels.

⌨Keyboard and Vim style

  • Keyboard is the primary way to navigate and operate; mouse is optional convenience.
  • Vim-inspired movement and shortcuts are consistent across system TUIs.
  • Help, focus, selection, search, and actions remain discoverable and usable without a mouse.

CLITerminal + filesystem

  • System capabilities are reachable through commands and TUIs.
  • Use inspectable text configuration and filesystem interfaces where appropriate, so users and tools can understand how the system is set up.
  • Keep interface behavior accessible to scripts and automation instead of hiding controls in a graphical app.

MONSystem monitor

  • CPU totals/per-core/load/temperature; GPU identity, use, and temperature when available.
  • Memory and swap; filesystem capacity and disk activity; network rates and totals.
  • Process search, sorting, useful columns, and process tree; confirm any process-changing action.
  • Predictable live sampling; unavailable readings shown as unavailable, never fabricated as zero.

SYSSystem management

  • Consistent ruki commands and TUIs for system areas such as network, packages, services, processes, users, storage, information, logs, and configuration.
  • Keyboard-driven workflows expose status, actions, and results consistently.
  • System tools are designed as usable interfaces for both people and authorized automation.

AIIntegrated AI agents

  • AI agents are a built-in part of the distribution's system-management experience, not a detached chatbot issuing random shell commands.
  • Agents use documented ruki commands or explicit system tools and filesystem interfaces, with clear capabilities and permission boundaries.
  • Show planned actions, require approval for risky changes, record outcomes, detect dangerous operations, and support rollback where practical.

What to avoid

Explicit boundaries in the requirements

×Do not turn it into

  • A new kernel or operating system written from scratch.
  • A collection of unnecessary replacements for established Linux tools.
  • Just an Arch theme or just a window-manager configuration.
  • A GUI-led desktop where essential system management requires pointing and clicking.

!Do not do this while building

  • Start with a custom ISO; first prove the useful ruki workflows on existing Arch.
  • Give an agent unrestricted shell access or let it execute arbitrary generated commands.
  • Hide system configuration and actions behind interfaces unavailable to terminal users or agents.
  • Fake missing hardware or permission-limited metrics as zero values.

Build in this order

Sequence from the requirements

Keyboard-first ruki

Prove the TUI monitor and CLI on existing Arch, with Vim-style controls and reliable system readings.

System tools + files

Build consistent TUI/CLI workflows and inspectable filesystem interfaces for system setup and management.

Integrated agents

Give agents documented tools to inspect and manage rukiOS. Bound permissions, review risky plans, and record outcomes.

Distribution / ISO

Package the working environment and agent interfaces into a reproducible rukiOS install.

First milestone: prove the keyboard-first TUI and CLI on existing Arch. Design system interfaces so a built-in agent can use them later. Build the custom distribution image after those interfaces work.
